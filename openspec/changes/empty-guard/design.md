## Context

В текущей ветке `NewCardForm` — статичная заглушка: `<input>` не контролируется, кнопка «Добавить» не имеет обработчика, пустой ввод не блокируется. Ветка `feature/server-cards` содержит рабочую реализацию: контролируемый `<input>`, `useMutation` для `createCard`, `useQueryClient.invalidateQueries` для обновления доски, валидация `title.trim()`.

API-функции уже есть в `client/src/api/cards.ts`:
- `fetchCards()` — GET `/api/cards`
- `createCard(title: string)` — POST `/api/cards` с телом `{ title, isDone: false, isUrgent: false }`

## Goals

- Карточка с непустым названием сохраняется на сервере и появляется на доске.
- Пустой ввод и ввод из одних пробелов блокируется — кнопка «Добавить» неактивна.
- Минимальные изменения — переиспользовать паттерн из `feature/server-cards`.

## Decisions

### Decision 1: Подход к валидации пустого ввода

**Вариант A — Блокировка кнопки (выбрано)**

Кнопка disabled, пока `title.trim()` пуст. Реализуется через `disabled={isPending || !title.trim()}`.

*Плюсы:*
- Неотправляемая форма — пользователь сразу видит, что ввод пуст.
- Не требует дополнительного состояния (флага ошибки).
- Паттерн уже используется в `feature/server-cards`.
- Минимум изменений в компоненте.

*Минусы:*
- Пользователь не видит текстового сообщения об ошибке (только disabled-кнопка).

**Вариант B — Текстовое сообщение об ошибке**

При попытке отправить пустую карточку показывать под полем текст «Введите название карточки».

*Плюсы:*
- Явное сообщение об ошибке.
- Кнопка остаётся видимой (не «гаснет»).

*Минусы:*
- Требует дополнительного состояния (`showError`, `errorText`).
- Пользователь может нажать кнопку и увидеть ошибку — лишний шаг.
- Больше кода в компоненте.

**Выбор:** Вариант A. Для задачи «защита от пустой карточки» достаточно disabled-кнопки — это простой и понятный сигнал. Текстовое сообщение добавит избыточную сложность.

### Decision 2: Подход к хранению состояния карточек

**Вариант A — React Query (выбрано)**

Использовать `useQuery` в `App.tsx` для загрузки и `useMutation` в `NewCardForm` для создания. Кэш инвалидируется после успешного добавления.

*Плюсы:*
- Паттерн уже реализован в `feature/server-cards`.
- Автоматическое обновление UI после мутации.
- `api/cards.ts` уже экспортирует `createCard` и `fetchCards`.

*Минусы:*
- Требует установки `@tanstack/react-query` и настройки `QueryClient` (если ещё не сделано).

**Вариант B — Локальный `useState`**

Хранить карточки в `useState` в `App.tsx`, при создании — `setCards(prev => [...prev, newCard])`.

*Плюсы:*
- Не требует внешних зависимостей.

*Минусы:*
- Не синхронизируется с сервером — добавленная карточка исчезнет при перезагрузке.
- Дублирует логику с `feature/server-cards` — нужно будет рефакторить позже.
- Не решает задачу сохранения на сервере.

**Выбор:** Вариант A. Задача требует, чтобы карточка сохранялась на сервере и появлялась на доске. React Query — уже проверенный в этом проекте паттерн.

## Plan

1. **NewCardForm.tsx** — сделать контролируемым:
   - `useState("")` для `title`.
   - `useMutation` с `mutationFn: createCard`.
   - `onSuccess`: очистить поле, инвалидировать кэш карточек.
   - `onSubmit`: `title.trim()` — если пусто, пропустить.
   - `disabled={isPending || !title.trim()}` на кнопке.

2. **App.tsx** — подключить серверные данные:
   - `useQuery({ queryKey: ["cards"], queryFn: fetchCards })`.
   - Заменить хардкод-массив на `data: cards`.

3. **NewCardForm.module.css** — проверить, что `.button:disabled` уже есть (есть в текущем файле).

## Impact

- `client/src/components/NewCardForm/NewCardForm.tsx` — контролируемый ввод, мутация, валидация.
- `client/src/App.tsx` — `useQuery` вместо хардкода.
- `client/src/api/cards.ts` — используется `createCard`, `fetchCards` (без изменений).
