# Proposal: delete-card-api

## Why

После переезда с мок-сервера (`json-server`) на собственный Express-сервер сломалось удаление карточек с доски. Клиент отправляет `DELETE /api/cards/:id`, но сервер не обрабатывает этот запрос: маршрут объявлен без параметра `:id`, контроллер читает идентификатор из `req.query` вместо `req.params`, а сервис содержит баг, из-за которого `deleteCard` всегда возвращает `false`. Клиентский метод `deleteCard` проверяет `response.ok` и выбрасывает ошибку при неуспешном статусе — текущий HTML-ответ 404 приводит к `throw`. JSON-ответы на ошибки требуются по KAN-3; сам клиентский `deleteCard` тело ответа не разбирает.

## What Changes

- Добавить маршрут `DELETE /cards/:id` в `cards.router.ts`
- Исправить контроллер `remove`: читать `id` из `req.params.id`, отвечать `204 No Content` при успехе, `404 JSON` при отсутствии карточки
- Исправить сервис `deleteCard`: сравнивать длины массивов до переназначения `cards = newCards`
- Добавить в `index.ts` middleware 404 (JSON) для неизвестных путей и error-middleware (4 параметра) для непредвиденных ошибок
- Клиентский код (`client/`) не изменяется

## Capabilities

### New Capabilities

- `card-deletion-api`: Удаление карточки по идентификатору из URL-пути. Сервер отвечает `204` при успехе (пустое тело), `404 JSON` при отсутствии карточки или неизвестном маршруте, `500 JSON` при непредвиденных ошибках. Запрос `DELETE /cards` без `:id` получает общий `404 JSON`.

## Impact

| Область | Влияние |
|---|---|
| `server/services/cards.service.ts` | Исправление `deleteCard` — сравнение длин до переназначения |
| `server/routes/cards.router.ts` | `delete('/cards', ...)` → `delete('/cards/:id', ...)` |
| `server/controllers/cards.controller.ts` | Возвращает `204` при успехе или `404 JSON` при отсутствии карточки; неожиданные ошибки обрабатывает общий обработчик `500` |
| `server/index.ts` | Добавление 404-JSON и error-middleware |
| `client/` | Не изменяется (критерий приёмки) |

**Зависимость:** клиентская кнопка удаления и функция `deleteCard` добавлены в PR #6 (ветка `feature/delete-card`), который ещё не слит в `main`. Проверка через интерфейс отложена до подключения клиентской части KAN-2. Серверная часть может быть реализована и проверена независимо через `curl`.
