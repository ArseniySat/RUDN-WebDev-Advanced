## Purpose

Описывает серверное поведение при удалении карточки по идентификатору
и обработку ошибок (неизвестные маршруты, непредвиденные сбои).

## ADDED Requirements

### Requirement: Удаление карточки по идентификатору из пути
Сервер SHALL удалять карточку, идентификатор которой указан в параметре
пути `:id` запроса `DELETE /cards/:id`.

#### Scenario: Существующая карточка удаляется по ID из пути
- **WHEN** отправлен `DELETE /cards/<existing-id>`
- **THEN** карточка с указанным `id` удаляется из хранилища

#### Scenario: Конкурирующие ID из пути, query и тела
- **WHEN** отправлен `DELETE /cards/<path-id>?id=<other-id>` с телом `{ "id": "<other-id>" }`, где `path-id` и `other-id` — разные существующие карточки
- **THEN** сервер удаляет только карточку по `path-id` из пути, карточка `other-id` сохраняется

### Requirement: Успешное удаление возвращает 204 без тела
Сервер SHALL отвечать статусом `204` и пустым телом при успешном удалении.

#### Scenario: Ответ 204 при удалении существующей карточки
- **WHEN** карточка успешно удалена
- **THEN** сервер отвечает `204 No Content` без тела

### Requirement: Остальные карточки сохраняются
Сервер SHALL удалять только одну карточку по указанному идентификатору.

#### Scenario: Остальные карточки сохраняются при удалении
- **WHEN** удалена одна карточка
- **THEN** все остальные карточки остаются в хранилище без изменений

### Requirement: Удалённая карточка не возвращается при GET
После удаления карточки запрос `GET /cards` SHALL не возвращать удалённую карточку.

#### Scenario: Последующий GET не содержит удалённую карточку
- **WHEN** карточка удалена через `DELETE /cards/<id>`
- **THEN** последующий `GET /cards` не возвращает удалённую карточку

### Requirement: Удалённая карточка не возвращается после обновления страницы
После обновления страницы карточка SHALL не появляться снова,
если сервер не перезапускался.

#### Scenario: После обновления страницы карточка не возвращается
- **WHEN** карточка удалена и сервер не перезапускался
- **THEN** карточка не появляется на доске после обновления страницы

> **Примечание:** данные хранятся в переменной в памяти. При перезапуске
> сервера карточки восстанавливаются до начальных трёх.

### Requirement: Повторное удаление и неизвестный ID возвращают 404 JSON
Сервер SHALL отвечать `404 Not Found` с JSON-объектом, содержащим поле
`error` — непустую строку с описанием ошибки, при удалении несуществующей
карточки или при запросе с неизвестным идентификатором. Сервер не должен
завершаться и продолжать обрабатывать запросы.

#### Scenario: Повторное удаление удалённой карточки
- **WHEN** карточка уже удалена и отправлен повторный `DELETE /cards/<id>`
- **THEN** сервер отвечает `404 Not Found` с JSON-объектом `{ "error": "..." }`

#### Scenario: Удаление по неизвестному ID
- **WHEN** отправлен `DELETE /cards/<nonexistent-id>`
- **THEN** сервер отвечает `404 Not Found` с JSON-объектом `{ "error": "..." }`

#### Scenario: Сервер не завершается после 404
- **WHEN** сервер ответил `404` на удаление несуществующей карточки
- **THEN** сервер не завершается и продолжает обрабатывать запросы

### Requirement: Неизвестные маршруты возвращают 404 JSON
Сервер SHALL отвечать `404 Not Found` с JSON-объектом, содержащим поле
`error` — непустую строку с описанием ошибки, на любой запрос к маршруту,
который не определён в роутерах.

#### Scenario: Неизвестный маршрут для GET
- **WHEN** отправлен `GET /нет-такого-пути`
- **THEN** сервер отвечает `404 Not Found` с JSON-объектом `{ "error": "..." }`

#### Scenario: Неизвестный маршрут для POST
- **WHEN** отправлен `POST /нет-такого-пути`
- **THEN** сервер отвечает `404 Not Found` с JSON-объектом `{ "error": "..." }`

#### Scenario: DELETE /cards без ID получает общий 404 JSON
- **WHEN** отправлен `DELETE /cards` без параметра `:id`
- **THEN** сервер отвечает `404 Not Found` с JSON-объектом `{ "error": "..." }`

#### Scenario: Неизвестный маршрут для DELETE
- **WHEN** отправлен `DELETE /нет-такого-пути`
- **THEN** сервер отвечает `404 Not Found` с JSON-объектом `{ "error": "..." }`

### Requirement: Неожиданная ошибка возвращает 500 JSON
Сервер SHALL отвечать `500 Internal Server Error` с JSON-объектом,
содержащим поле `error` — непустую строку с описанием ошибки,
при непредвиденной ошибке.

#### Scenario: Обработчик ошибок отвечает 500 JSON
- **WHEN** происходит непредвиденная ошибка на сервере
- **THEN** сервер отвечает `500 Internal Server Error` с JSON-объектом `{ "error": "..." }`

## Constraints

- Клиентский код (`client/`) не изменяется.
